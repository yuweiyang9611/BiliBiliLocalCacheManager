# 桌面需求实施计划

对应 [已确认需求](2026-09-22-desktop-baseline.md) 与 [待执行验收](2026-09-22-desktop-acceptance.md)。以下为建议的实施顺序与交付门槛，不表示功能已经动工，也不构成自动提交、推送、合并或发布的授权。

状态：本计划于 2026-09-22 确认，用户随后授权实施。M1-M5 的代码和自动验证进展、M6 的实测及待完成项见 [实施记录](2026-09-23-implementation-status.md)，不以计划本身表示验收通过。

## 原则与依赖

- 保留已有删除保护、导出原子提交、取消结果确认、Host 生命周期隔离、查询缓存及诊断安全边界。
- 先建立稳定的选择/目标契约，再让播放、导出和回收站消费它；不在渲染器新增任意文件路径授权。
- 用户体验顺序以播放、导出、清理为主。CLI 退出与依赖准备可独立开展，但发布资产不能只改其中一侧。
- 每阶段先补针对性回归，再实施；新增类型/字段同时更新 Host、主进程运行时校验、Preload、UI 与契约测试。
- 技术方案不得把未确认的功能悄悄带入范围，例如多库聚合、内置播放器、拖动队列、画质面板或手机传输。

| 阶段 | 前置 | 对应需求 | 完成门槛 |
| --- | --- | --- | --- |
| M1 桌面独立交付 | 已确认范围 | R02、R03、R15 | CLI 退出且桌面构建、测试、四包校验一致 |
| M2 缓存库与选择 | 稳定目标身份设计 | R04-R06、R13 | 跨页/跨视频选择及只读并发可验证 |
| M3 播放路径 | M2 | R07-R08 | 顺序、指定播放器、失败重试、保护不回归 |
| M4 导出流程 | M2；产物来源/处理方案设计 | R09-R10 | 许可不可绕过，统一目录，整批原子发布 |
| M5 分 P 回收站 | M2；物理目标/兼容设计 | R11-R12 | 分 P 删除恢复安全，旧数据仍可恢复 |
| M6 全链路验收 | M1-M5 | R01-R15 | 回归、性能、打包及真实桌面证据齐全 |

M1 与 M2 的准备可分别进行；只有相关阶段均完成，才能宣称整套需求交付。各阶段可以拆为小提交/PR，但每次都应保持现有功能可用。

## M1 桌面独立交付

主要范围：solution、CLI 与专属测试、`.github/workflows/ci.yml`、`release.yml`、`scripts/build-release.ps1`、发布验收校验器及其夹具、README/兼容性与验收说明。

1. 盘点 CLI 专属代码与共用能力，确认桌面 Host 仍独立引用 Core/Playback。删除纯 CLI 入口/解析测试，保留或迁移仍约束桌面的共用安全回归。
2. 移除 CLI 项目、打包、smoke 与文档入口；保留桌面 Host 的自包含发布、签名、注入环境清理和启动检查。
3. 原子地更新未来四类桌面包的资产集合、SHA 清单、验收格式/校验器和负面夹具，移除依赖 CLI 命令执行的验收步骤。
4. 明确新旧验收记录格式/版本的处理，不能把旧六包记录改名就视为新四包验收，也不能改写历史 Release 资产。
5. 只修订本阶段已经改变的当前行为说明。启动扫描、导出、回收站等尚未实施的未来要求仍留在需求文档，不提前声称已支持。

验收：A01-A03、A41-A42；运行完整 .NET 回归、前端检查、构建与可用平台打包自检。本阶段不创建真实 Release。

## M2 缓存库、选择与只读并发

主要范围：桌面 `App.tsx`、库/详情页面、共享契约、Preload、IPC、Host 索引查询与参数解析；不因个人工具定位取消运行时响应校验。

1. 固定视频及分 P 的稳定目标身份和排序来源；选择集合与当前页分离，不以勾选时的显示位置或任意路径作为磁盘目标。
2. 实现视频/分 P 互斥、跨页及跨视频分 P 选择、完整清单和准确数量；统一处理查询、目录、索引变化导致的清空。
3. 在任务提交边界冻结目标和顺序；浏览产生的新状态不能改变任务范围，也不能使旧搜索/详情结果覆盖当前页面。
4. 允许媒体长任务中的搜索和详情读取；仍禁止其他副作用任务及目录切换，维持按窗口搜索抢占与过期索引拒绝。
5. 默认搜索保留现有标题、UP、BV/AV，分 P 名称从默认参与改为默认关闭、可选开启；更新启动扫描默认值，保留手动刷新、用户关闭选择、未完成开关及既有高级设置。先设计新/旧配置兼容，不通过无条件重置设置改变用户选择。
6. 保留扫描问题的全量统计、有界明细、受限定位和自身变更后的刷新；操作已提交结果不得被刷新失败抹去。

验收：A04-A14、A33-A36；确定性 Renderer/IPC/Host 测试覆盖选择、抢占、乱序响应及提交快照。详细分 P 操作在对应功能阶段接入，不能先把按钮接到整视频删除。

## M3 播放顺序与播放器策略

主要范围：媒体目标解析、Playback 启动器、批量准备及结果 UI。

1. 将冻结的跨视频/跨页目标按索引顺序、P 序号排序和去重，保持整批准备后只交接一次。
2. 让系统默认、mpv、VLC 偏好严格遵守用户选择；启动失败返回原因，不换另一个播放器。
3. 保留部分失败时交接成功项、失败项精确重试、全失败/取消不启动和本地 M3U8 的安全检查。
4. 扩展新目标规模的保护测试，覆盖长准备、全部产物、并发与跨实例清理；准备保护活动不能续期停滞超时。

验收：A15-A19、A33-A36；真实 FFmpeg 集成与最终桌面文件关联/mpv/VLC 分开记录，不把 Process.Start 成功当作真实播放验收。

## M4 质量确认与统一导出

主要范围：Playback 处理方案/产物来源信息、Host 媒体导出、IPC 文件选择与许可契约、导出结果/确认 UI、文件命名。

1. 先设计可验证的处理方案与产物来源描述，区分转封装、音频转码、视频转码和未知；不能只凭 MP4 扩展名或缓存命中判断无损。
2. 将需要确认的项目/原因/影响返回界面；许可绑定实际目标与处理方案，源或方案变化时重新判断。具体契约表示在编码前做兼容与安全评审。
3. 运行途中出现新的转码要求时返回本批未发布及待确认明细；确认后重试完整批次，安全复用可验证产物。
4. 单 P、单视频、多选统一选择目标目录并在同卷暂存完整批次，内部建立视频目录和各 P 文件；保留中文与可移植命名检查。
5. 发布时一次性重命名整个批次，编号避让已有批次且绝不覆盖。竞争、失败、取消和提交后的实际结果均按已有提交边界处理。

验收：A20-A25、A33-A36。特别验证旧播放产物绕过许可、准备中源变化、重名竞争及单 P 旧保存对话框覆盖路径不再绕过统一规则。

## M5 分 P 回收站与维护

主要范围：Core 文件系统管理、回收站元数据和事务、Host 存储/回收站、桌面确认/结果/撤销、统计与分页。

1. 在实现前对照真实结构与隔离夹具，建立逻辑分 P 到物理缓存目录的映射；处理多候选、重复 P、残余文件和整个视频目标，映射不明确时安全拒绝。
2. 复用当前目录身份、句柄、根范围和跨进程变更互斥；不能为支持细粒度删除移除复核或允许渲染器传入任意路径。
3. 设计版本化元数据和恢复事务，保留旧整视频条目的读取/恢复；未来版本、不可信条目及目录竞争仍安全处理。
4. 支持整视频、单视频多 P、跨视频多 P 移入及撤销；确认和结果都准确表达视频数、P 数及成功/失败范围，保护未选 P。
5. 恢复到已存在父视频目录时只检查实际目标 P 冲突；冲突保留原回收站内容，不覆盖，非冲突项可完成恢复。
6. 接通快照分页、完整统计和强化清空确认，保持 Linux 不可逆删除限制；自动维护仍只触及可重建的受管产物。

验收：A26-A36。使用故障注入、身份替换、旧数据兼容和临时目录测试；不得先在真实用户缓存上试验删除。

## M6 全链路验收与文档收尾

1. 运行完整 .NET 回归、真实固定 FFmpeg 集成、前端类型检查/测试/构建以及可用平台包自检；纯 CLI 测试退出不等于允许共用安全覆盖减少。
2. 在记录配置的 Windows 验收机上测试 10,000 条多 P 库的真实搜索、翻页、长任务响应及内存，区分索引构建、Host 微基准、IPC 和 UI 的测量边界。
3. 保留 50,000 条辅助压力与取消参考，使用确定性测试约束缓存/排序行为，不新增脆弱的跨机器秒数 CI 门槛。
4. 当前实现真正完成后同步 README、兼容性步骤、验收记录说明与四包校验；清点旧的启动扫描默认、CLI、单 P 覆盖和平铺导出文案。
5. 在 Windows 两种包及规定 Linux 真实桌面矩阵上完成实际测试。没有条件执行的项目列为待完成，不填造通过。
6. 只有后续明确要求发布时才创建公开预览；只有同一批最终资产和真实验收记录都合格后才允许转正。本计划本身不触发这些远程操作。

验收：A01-A44；最终报告区分已实现、自动验证通过、人工待完成及已知限制。

## 阶段交付格式

每阶段说明关联 R/A 编号、行为变化、数据/协议兼容处理、实际执行的验证及未执行项。代码实现、提交推送、合并和发布状态分别报告，不把文档落地或单一 CI 通过当作所有需求已经完成。
