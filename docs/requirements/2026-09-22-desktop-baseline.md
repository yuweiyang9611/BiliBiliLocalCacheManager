## R01 产品边界

来源：Q1-Q5。

- 优先服务用户自己的日常使用，而非通用媒体平台或命令行自动化产品。
- 主流程优先级：查找并播放、导出归档、清理空间。排序不意味着后两项可以缺失。
- 仅处理已存在于可访问本地目录中的缓存，不负责手机连接、设备传输、视频下载或在线媒体播放。
- 桌面扫描、搜索、播放、导出、回收站、磁盘维护及既有设置、诊断等能力保留。
- 保持已支持的缓存结构兼容；未知或无法可靠识别的内容报告问题，不猜测处理，也不据此宣称兼容所有客户端版本。

## R02 桌面入口与 CLI 退出

来源：Q28-Q29、Q31；替代早期“保留 CLI”的建议。

- 不再提供或维护独立 CLI；后续移除 CLI 项目、专属测试、命令示例、构建和打包发布步骤。
- 内部 Desktop Host 与共用 Core、Playback 能力继续服务桌面。不能因移除 CLI 而丢失仍适用于桌面的安全回归覆盖。
- 不迁移 CLI 独有的绕过回收站直接永久删除、脚本免确认、不可信回收站清理、额外命令行搜索参数等入口。桌面已有高级搜索仍保留。
- 不追溯删除历史 Release、历史包或改写 Git 历史。

## R03 平台范围

来源：Q4、Q27。

- Windows 是主要验收平台，Linux 保留支持；既有 x64 桌面环境矩阵不因个人使用定位自动缩减。
- Windows 按完整桌面流程验收。Linux 应可扫描、搜索、播放、导出、移入回收站、恢复及执行受保护的产物维护。
- Linux 暂不开放原缓存永久删除或应用回收站永久清空，界面需明确限制。不可因自动测试通过而宣称该能力可用。
- 保留现有依赖与平台安全边界；本轮不新增 macOS、ARM64 或原生 Wayland 承诺。

## R04 缓存库与扫描

来源：Q6-Q9、Q25。

- 只记住一个缓存根目录，需要时手动切换；不增加最近目录列表、多目录库或聚合搜索。
- 默认启动扫描，允许关闭，并保留手动刷新；不持续监听外部文件变更。自身删除、恢复后自动更新相关列表。
- 默认启用不能变成每次启动强制启用；已有明确关闭、未记住路径、无有效目录等情况须在实施时分别处理和验证。
- 主列表按视频条目聚合，详情展示分 P。视频数与分 P 数分开计算和标示。
- 默认只展示完整缓存，保留包含未完成缓存的开关。个别损坏或不可访问目录不阻止其他正常内容入库。
- 扫描结束展示问题数量、原因和受限定位入口；沿用最多 100 条明细、完整汇总计数与截断提示。无法识别的内容不自动删除。

## R05 查找规则

来源：Q12、Q31。

- 默认搜索标题、UP 主、BV/AV 号；分 P 名称默认不参与，可选择开启。
- 保留桌面已有精确/前缀/包含匹配、分词、任意/全部词及大小写等高级规则，不要求每次使用重新配置。
- 沿用已确认的查询防抖、抢占、过期结果隔离和查询缓存，不用隐式重扫掩盖失效索引。
- 不因保留高级搜索而自动把 CLI 独有参数全部加入桌面。

## R06 选择与操作范围

来源：Q7、Q10、Q13、Q32。

- 视频级与分 P 级选择互斥；勾选另一层级时清空原层级选择。仅聚焦视频、打开详情或查看别的视频不改变选择。
- 同一次搜索内跨页保留选择。分 P 模式允许跨视频、跨详情页选择多个分 P。
- 显示准确范围与数量，提供完整已选清单和清空入口，例如“已选 N 个视频中的 M 个分 P”。不能只展示当前页数量。
- 修改搜索条件、重新扫描或切换目录时清空选择；索引失效时不能继续用陈旧目标执行操作。
- 提交任务时固定目标快照，后续浏览、翻页或选择变化不能改变已提交任务。去重和任何容量限制均不得静默丢弃目标。

## R07 播放交接与顺序

来源：Q3、Q14、Q23，以及既有批量播放约定。

- 保留系统默认播放器、mpv、VLC 三种偏好；选定播放器启动失败时显示原因，不自动改用其他播放器。
- 按视频在库列表中的顺序、视频内部 P 序号升序准备，去重后交接。点击顺序、往返翻页或取消再选不改变队列顺序。
- 整批准备后只启动一次播放器；单项保持直接交接，多项使用经过验证的本地 UTF-8 M3U8。不新增可拖动排序的队列。
- 部分准备失败时交接成功项并列出失败明细，支持仅重试失败项；全部失败或准备取消时不启动。
- 启动成功只表示“已交给播放器”，不代表已经开始或完成实际播放。保持仅本地媒体、标题清理与路径安全检查。

## R08 播放产物保护

来源：Q19 及保留的既有安全约定。

- 每个准备完成的产物立即保护，准备期间每 60 秒将本批产物保护续至至少 6 小时后。
- 交接前按至少 6 小时与队列总时长加 1 小时的较大值保护播放列表及全部产物，不受 64 项会话上限截断。
- 取消或失败停止续期，不缩短已有期限；续期失败停止后续准备且不启动播放器。保护写入不是有效任务进度。
- 持久保护在应用重启后仍有效，过期后按维护策略处理。外部播放器暂停超出保护期限的实际状态无法通过系统关联可靠获知，不承诺永久保护。

## R09 导出质量与确认

来源：Q15、Q18、Q22。

- 只输出普通 MP4，以保留原质量为目标；能直接转封装就不重新编码，不增加分辨率、码率或压缩参数面板。
- 需要转码时先列出项目、原因和影响，取得确认后才执行；无法可靠处理时报告失败，不虚称无损。
- 途中才发现新的转码需求时，结束当前未发布尝试并展示需求，确认后重试完整批次，不无限暂停任务等待用户。
- 重试可复用已准备产物；此前播放或导出生成的转码文件也不能绕过本次所需确认。

## R10 导出组织与原子发布

来源：Q16-Q17、Q21；以 Q21 的批次层为准。

- 单视频、单 P 与多选统一使用目标目录中的新批次目录；每个视频一个子目录，各分 P 分别为 MP4，不将多个 P 合成一个视频。
- 目录示例为 `导出目录/cache-export/视频标题_AV号/P001_分P名称.mp4`。
- 批次重名时创建 `cache-export (2)` 等新目录，不覆盖旧批次，不把本次结果写入已有视频文件夹。
- 整批准备成功才一次性发布；提交前取消或任何准备失败都不发布半批结果。提交后迟到取消不能覆盖真实成功。
- 失败后明确说明本批未发布，重试整批且复用可用产物；内部临时准备文件不能显示成已经完成的导出。
- 中文、特殊字符、重复名称和长路径需安全命名；具体命名实现不得改变层级、目标集合或不覆盖约定。

## R11 回收站与恢复

来源：Q11、Q20、Q26、Q31-Q32。

- 支持整个视频或所选分 P 移入应用回收站并恢复，包含跨视频选择的分 P；不得误删同视频其他分 P。
- 移入前一次汇总确认，明确视频数、分 P 数和范围，成功后提供撤销入口。
- 分 P 恢复时父视频目录存在不算冲突；同一分 P 目标位置已有内容时不覆盖、不擅自合并，保留冲突条目并说明原因。无冲突条目可恢复，结果必须如实列出部分成功。
- Windows 永久清空需强化确认、输入确认文字，并明确不可恢复；保留完整条目集合和物理身份复核，不新增绕过回收站的桌面永久删除入口。
- 保留旧回收站的安全读取/恢复能力，不用新元数据要求把原有正常条目直接变成不可恢复数据；未来或不可信格式继续安全拒绝。

## R12 维护边界

来源：Q19、Q27。

- 自动维护只可删除可重建的临时播放文件、播放列表与转码产物，且遵守保护期、活动任务及受管目录限制。
- 原始缓存、导出文件和应用回收站不自动删除；空间不足时提示，由用户选择清理方式。
- 保留存储统计、保留期/容量策略及手动维护入口，不能为释放空间跳过保护或平台限制。

## R13 长任务与结果确认

来源：Q24、Q33 及保留的可靠性约定。

- 播放准备或导出期间允许只读浏览、搜索、查看详情；禁止新的播放、导出、删除、恢复、清理或切换目录。
- 扫描、播放准备、导出与磁盘维护采用 10 分钟无有效进展超时，无固定总时长上限。重复、回退、等待提示、耗时增长、其他请求事件和保护续期不续期。
- 取消与超时均向 Host 请求取消，原请求继续跟踪，以最终结果为准；不可取消提交段返回实际结果。
- 首次取消后立即显示“正在取消”；从取消请求发出起 30 秒仍未确认时显示“结果待确认”，此期限不被进度延长。不强杀 Host，不重复发送取消，不自动重试，继续限制有副作用操作。
- Host 退出导致无最终结果时明确“结果无法确认”；用户核对实际输出或磁盘状态后才能解除限制。
- 正确区分全部成功、部分失败、全部失败、取消、待确认及无法确认，不以成功提示掩盖失败。
- 保留 Host 实例隔离、按窗口抢占搜索、受限 IPC/路径定位、响应校验与诊断脱敏，不通过削弱这些约束满足新交互。

## R14 性能目标

来源：Q8、Q30。

- 正式规模为 10,000 条视频记录，覆盖多分 P，视频数与分 P 总数分别记录。
- 在约定的 Windows 验收机上，已完成扫描后，从停止输入到搜索结果可见目标不超过 1 秒，包含 350 毫秒防抖；翻页到内容可见目标不超过 500 毫秒。
- 扫描、播放准备和导出中界面可响应，进度与取消状态可见；不规定所有数据/设备上的统一总完成时长。
- 记录机器、数据和测试条件；上述目标不是所有 CI 机器必须满足的固定耗时门槛。不能用后端微基准替代桌面端到端测量。
- 保留已有 50,000 条辅助压力参考，但不将其升级为本次正式桌面体验承诺。

## R15 发布与验收

来源：Q29、Q31、Q33，以及保留的发布约定。

- 完成 CLI 退出后，未来交付包为 Windows NSIS、Windows ZIP、Linux DEB、Linux RPM 四种；校验清单、验收记录及打包流程必须一致更新。
- 所有标签先公开预览，真实验收后才把同一版本、同一批包转正，不重新构建；rc/beta 等预发布标签不能转正。
- 真实 Windows/Linux 桌面测试与 CI 分开记录；保持既有 Windows 10/11、Ubuntu、Debian GNOME/KDE、Fedora 至少一种 GNOME/KDE 的必测范围。
- 校验器核对记录、版本、提交、资产集合及实际 SHA-256，任何缺失、失败或不符均阻止转正；记录完整性检查不替代真人测试。
- 本文和配套勾选清单不是已完成的 Release 验收记录。
